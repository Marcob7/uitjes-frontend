# Internationalisation (NL / EN)

## Architecture

Public pages use locale-prefixed URLs: `/nl/...` and `/en/...`. `middleware.ts` redirects old unprefixed URLs to the default locale (or the saved preference) and rewrites prefixed requests internally to the existing App Router route. This preserves one page implementation per route while making locale available during SSR through `getRequestLocale()`.

Dutch is the default locale. The `uitjes_locale` cookie records an explicit language switch or direct locale URL and is used only when an older, unprefixed URL is opened. Middleware never updates it for a Next prefetch, so speculative loading cannot undo a user choice. We intentionally do not redirect repeatedly based on browser language: a user choice always wins and server-rendering stays predictable.

## Adding UI copy

Add the same semantic key to `messages/nl/common.json` and `messages/en/common.json`. Use feature namespaces such as `navigation.search` or `search.empty.title`; do not put language conditionals in components. Server components can call `getCommonMessages(getRequestLocale())`. Client components use `useLocale()` from `components/i18n/LocaleProvider`; it synchronises from the URL after client-side navigation, so the public route remains authoritative.

## Links, dates and numbers

Use `localePathname(path, locale)` for global/localised links. It removes a current prefix before adding the requested one. `LanguageSwitcher` retains query parameters and writes the preference cookie. Use `formatDate`, `formatNumber`, `formatRating`, and `formatCurrency` from `lib/i18n/format`; extend these shared helpers instead of embedding locale strings or month lists in views.

## SEO and routes

Use `getLocaleAlternates(pathname, locale)` and `getLocaleOpenGraph(locale, pathname)` in new `generateMetadata` implementations. They produce a locale-aware canonical, `nl`/`en` hreflang alternatives, and Open Graph locale. Add both locale variants of new indexable paths to `app/sitemap.ts`.

Dynamic route implementations remain in their current folders (for example `app/ontdek/[slug]`); locale is a request concern, not a duplicated route folder. Keep user-generated/backend content, proper names, event names, artists, and venues unchanged unless the backend later exposes authored translations. Only UI copy belongs in dictionaries.

## Migration pattern

When translating a feature: first move its UI strings to a semantic dictionary namespace; then obtain locale via the relevant server/client helper; then localise its links and formatting; finally update its metadata. Do not machine-translate runtime content or introduce `locale === "en"` ternaries in feature components.
